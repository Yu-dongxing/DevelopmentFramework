# 文件生命周期与精度修复说明

## 响应精度

`jackson.long-to-string=true` 向 Spring Boot 4 实际使用的 Jackson 3 注册序列化模块。
响应中的 `Long`、`long` 和 `BigInteger` 输出为字符串，包括分页、集合及嵌套对象。
前端提交的字符串 ID 仍按 Long 读取。关闭该配置后恢复默认数字输出。

## 上传与补偿

- 上传编排必须通过 Spring 事务代理调用。物理上传完成后立即注册事务同步回调，URL 构建、审计填充、保存异常或保存返回 false 都会触发回滚补偿。
- 外层事务回滚以及提交失败后确认回滚，均按上传结果中的桶和对象路径执行清理。事务结果未知时不删除对象，日志记录待核对的位置，避免误删实际上已提交的文件。
- 物理清理失败时，以独立事务新增 `sys_file` 补偿记录：`upload_status=0`、`is_deleted=1`、`physical_delete_status=1`。复用每分钟执行的文件清理任务，不新增表。
- 本地复制中断会清理本次创建的残片；云 SDK 上传报错后按本次唯一 Key 尝试清理可能已落盘的对象。
- 上传完成事件仅在最外层事务提交后发布。监听器应执行旁路处理；需要写数据库时必须开启新的事务。默认监听器使用虚拟线程异步执行。

补偿不是跨数据库和对象存储的分布式原子事务。如果数据库和存储同时不可用，任务无法持久化，会输出包含类型、桶、路径的错误日志，需要运维核对。进程在上传完成但补偿登记前被强制终止，同样需要对象与元数据对账；当前机制不承诺这一崩溃窗口的自动恢复。

## 删除与访问

- 逻辑删除保留物理文件和元数据。已逻辑删除的记录可再次提交 `physical=true`，升级为物理清理；重复请求保持幂等。
- 物理删除在数据库事务提交后执行。监听器重新读取待清理状态，正常记录和已完成记录不会触发删除。
- 删除失败保留任务并更新重试顺序；成功后只清理待删除状态的元数据。
- 本地静态资源只对存在正常、未删除元数据的文件开放。逻辑删除后返回 404，未登记文件也不公开访问；响应采用 `Cache-Control: no-store`。
- 本地目录中的历史文件必须先补齐 `sys_file` 记录。已经下载到客户端的副本无法撤回。
- OSS/MinIO 的公开直链绕过应用，逻辑删除不能撤销这些公开直链；需要立即撤销云端访问时，应使用物理删除，或另行部署私有桶和受控下载策略。CDN 已缓存的内容还需要按部署策略失效。

## 存储配置切换

- 删除和 URL 构建使用记录中的 `storage_bucket`。缺失历史桶时拒绝猜测位置，应先核对并补齐元数据。
- OSS 旧桶不复用当前桶绑定的 CDN 域名，使用该历史桶的标准访问地址。
- 配置了端点和凭据的云存储客户端不再受 `file.active` 限制；切换当前上传类型时，保留旧存储端点和凭据即可继续清理历史文件。
- 当前仍是每种存储类型一组端点/凭据。本次覆盖同端点切桶和切换存储类型；跨账号、跨端点或本地根目录迁移必须先完成对象迁移并核对配置，不能只替换地址后直接清理旧记录。

## 验证

从仓库根目录执行 ` .\mvnw.cmd clean test`。回归覆盖实际 MVC 精度、配置开关、字符串 ID 输入、外层回滚、确认回滚的提交失败、补偿持久化、逻辑删除升级、失败重试、历史桶、客户端保留及本地资源访问。
