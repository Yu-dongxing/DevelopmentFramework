# 数据库初始化与业务访问顺序

框架管理的 Hikari 数据源在自动建表成功后才发布给 Spring。业务 Mapper、JdbcTemplate、事务管理器及依赖它们的 Bean 使用原来的注入方式，既有定时任务和异步监听器无需增加等待代码。

## 启动顺序

1. 绑定 `spring.datasource` 与 `spring.datasource.hikari` 配置，创建内部连接池。
2. 使用未注册为 Bean 的专用 JdbcTemplate，复用现有扫描、方言、SQL 生成与初始化服务，完成表结构、索引、外键及默认数据初始化。
3. 初始化成功后返回业务数据源，依赖它的业务 Bean 才能完成创建。
4. 所属容器刷新完成后发布一次 `DatabaseInitializedEvent`，供可选扩展功能使用。

初始化不依赖公共 JdbcTemplate、Mapper 或业务 Service。不要在初始化链路引入这些依赖，否则会形成数据源创建循环。内部初始化服务实例与容器中的维护服务实例复用同一套实现；容器中的 `DatabaseInitService` 仍可供既有维护调用使用，但手动调用不会重新关闭业务数据源，也不会重发启动事件。

## 状态和通知

`DatabaseInitConfig.getStatus()` 返回当前容器状态：

| 状态 | 含义 |
| --- | --- |
| INITIALIZING | 正在创建连接池或同步数据库 |
| READY | 自动初始化成功 |
| FAILED | 初始化失败，数据源工厂抛出异常并关闭已创建的连接池，启动终止 |
| SKIPPED | `db.init.enabled=false`，由外部迁移或测试脚本提供结构 |

`SKIPPED` 不会发布自动初始化成功事件。事件来源是所属 ApplicationContext，父子容器中的监听器应按需检查来源。重复刷新通知不会导致同一配置实例重复发布事件。

扩展监听器可以监听 `top.yuxs.springbootdev.core.db.event.DatabaseInitializedEvent`，并按项目约定使用 `@Async("taskExecutor")` 处理异步业务。事件只通知，不负责解锁或阻止定时任务；任务与扩展监听器之间没有先后完成保证。必须在业务执行前完成的关键数据准备，应加入同步初始化流程，而非放入异步监听器。

## 配置与范围

保留现有 Hikari 配置，包括 URL、账号、驱动、连接池大小和超时；其他连接池类型会明确报错。外部 `JdbcConnectionDetails` 优先覆盖连接 URL、账号、密码和驱动，适配容器连接信息。没有外部连接信息时，Hikari 专属属性优先于普通 datasource 属性；`spring.datasource.name` 用于默认连接池名称。

`spring.datasource.hikari.data-source-class-name` 模式使用 `data-source-properties` 配置底层数据源，不再同时设置驱动类。该模式不能与外部 `JdbcConnectionDetails` 同时使用，框架会明确拒绝冲突配置，避免忽略 URL 或连接错误数据库。数据源由框架统一创建，不应另外定义同名或独立业务数据源绕过初始化。

数据源工厂显式声明 `@Lazy(false)`，全局懒加载也不会延后建表或漏发完成事件。扫描包不能为空；默认拒绝空扫描结果。如确实不需要任何实体，可显式设置 `db.init.allow-empty-scan=true`。实体类加载失败始终中止初始化。

屏障只覆盖使用框架数据源的关系型数据库访问，不覆盖 Redis、自行创建的 JDBC 连接、任务查库前的其他副作用。`READY` 表示本框架自动初始化完成，不代表所有 ApplicationRunner 或其他启动扩展均已完成。

默认数据检查失败会直接传播异常，不会当成表非空并跳过。数据库 DDL 不保证跨数据库事务回滚，初始化失败后可能留下部分已完成结构，应排除原因后重新启动。

这是单进程启动顺序保证，不包含多实例 DDL 互斥。多实例生产部署应由单独迁移流程提供结构，并在业务实例设置 `db.init.enabled=false`；不能依靠本地事件协调多个实例。

## 验证

回归测试使用独立 H2 空库，覆盖早期 Bean 查询、零延迟定时任务、异步事件、完成事件去重、全局懒加载、连接信息覆盖、数据源类模式、扫描错误、默认数据写入及其中途失败后的连接池关闭。

完整测试命令为 `.\mvnw.cmd clean test`。本地 MySQL 与 Redis 集成测试默认关闭；通过环境变量 `LOCAL_TEST_DB_USERNAME`、`LOCAL_TEST_DB_PASSWORD` 提供数据库凭据，再执行 `.\mvnw.cmd clean test -Ddb.integration.enabled=true` 可同时启用。测试连接本机 MySQL 3306 和无认证 Redis 6379，创建随机命名的 `codex_init_test_` 临时库，验证完整应用首次启动、重启、Mapper 查询、文件补偿任务和 Redis PING，结束后删除该测试库。不会修改现有业务库或写入 Redis 数据。
